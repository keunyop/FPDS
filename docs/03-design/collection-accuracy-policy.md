# 은행 상품 수집과 자동 승인 규칙

2026-11-21 · FPDS Admin의 현재 수집 기준

## 어떤 문서를 확보하는가

1. 한 번의 수집 범위는 국가, 은행, 상품 유형이다. 등록된 시장별 필수 항목과 은행의 공식 도메인을 확인한다. 상품명과 그 상품이 실제로 제공된다는 근거를 상세 문서에서 확보한다.
2. 상세 페이지 하나로 필수 항목이 확인되면 그 근거를 사용한다. 부족하면 해당 상품에서 직접 연결한 금리표·수수료표·약관을 찾는다. 공식 도메인에도 다른 국가와 상품의 문서가 있다. 링크와 최종 도착 주소에서 명시된 국가·언어를 검사한다.
3. 상대 링크는 캡처가 도착한 페이지의 디렉터리를 기준으로 해석한다. 문서를 요청할 때는 은행이 적은 상품·문서 식별자의 철자와 경로를 보존한다. 중복 판정에는 정규화한 주소를 사용한다. 같은 이름의 카드라도 다른 오퍼 식별자는 별개다.
4. 공통 약관을 여러 상품에 연결할 수 있다. 각 상품에 적용되는 표의 행, 제목, 각주 또는 명시적인 적용 범위가 확인된 항목만 사용한다. 포인트 교환, 보험, 다른 상품 신청 안내는 예금 중도해지의 근거가 될 수 없다.
5. PDF는 원문 형식을 확인하고 파싱한다. 오류 페이지, 실패한 다운로드, 이전 실행의 원문, AI가 제시한 미확인 주소로 현재 근거를 대체하지 않는다. 원본 바이트·체크섬·스냅샷·파싱 결과는 비공개 근거로 연결한다.

|---|---|---|
| 입출금계좌 | 계좌 상세, 계좌 서비스 요금표 | 기본 월 수수료, 면제 잔액·입금 조건, 일반 거래와 ATM 거래, 포함 횟수와 초과 건당 요금 |

| 정기예금·GIC·CD | 기간별 금리표, 상품별 중도해지 약관 | 기간과 같은 행의 금리, 만기 전 인출 가능 여부, 가능할 때의 대기 기간과 손실·수수료 |
| 신용카드 | 정확한 카드·오퍼의 가격 공시와 수수료표 | 구매 금리, 현금서비스 금리, 본카드 연회비, 첫해 면제와 기본 연회비 |
| 주택담보대출 | 상품 약관, 금리표, 금리 예시의 전제 | 고정·변동, 고정 기간과 상환 기간, 계약 금리와 비용을 포함한 예시 |
| 개인대출 | 해당 대출의 가격 공시, 상환 조건 | 대출 금액 범위, 금리 범위, 실제 상환 기간, 고객별 조건 |
| 신용한도 | 한도대출 약정, 금리 및 담보 조항 | 대출 한도, 담보 필요 여부, 기준금리와 가산금리 |

## 언제 값을 채택하는가

- **하나의 값마다** 현재 실행에서 선택·파싱된 공식 원문, 해당 문서의 위치, 정확한 인용문, 대상 상품, 타입과 단위가 맞아야 한다. 숫자만 발췌해 주변의 예외·수식어·다른 가격을 지우지 않는다. AI는 문서와 구절을 고를 수 있고, 자동 승인에는 같은 검증을 적용한다.
- **조건은 값의 일부다.** 면제 조건이 붙은 월 10달러는 기본료 10달러와 면제 조건으로 보존한다. 월 이율을 연 이율로 바꾸거나 기간 범위에서 대표 일수를 만들어 내지 않는다. 연 이율, APR, APY와 이자 지급 주기를 각각 구분한다.
- **중도해지**는 인출 가능과 금지를 반대 의미로 처리한다. “만기 전 해지 불가”는 금지의 근거다. “첫 30일 동안 불가”만으로 나머지 기간의 조건을 확정할 수 없다. 허용·금지가 충돌하거나 예외를 해석할 근거가 부족하면 가능 여부를 미확정으로 남긴다. 검증된 금지가 있어야 중도해지 불이익 확인을 생략할 수 있다.
- **통화**는 명시된 근거를 우선한다. 통화가 미공개이고 충돌 근거가 없을 때만 CA/CAD와 US/USD의 등록된 기본값을 적용하고 그 사유를 남긴다.
- **저장**하려면 상품 식별·통화·시장별 필수 조건 및 설정된 추가 필수 항목을 충족해야 한다. 필수 근거 누락은 후보 자동 제외로 기록한다. 선택 정보는 같은 원문이 입증할 때 보존한다. 모르는 값을 0이나 거짓으로 채우지 않는다. 상품 승인에 수동 대기열을 추가하지 않는다.
- **버전 변경** 시 파싱 결과가 달라지면 파서 버전을 올린다. 자동 승인은 현재 검증 버전의 결과를 사용한다. 중도해지 판정 변경 전의 정기예금 검증 결과는 다른 저장 경로에서도 재검증해야 한다. 과거 상품·변경 이력은 보존한다.

## 실패를 처리하고 검증하는 방법

필수 근거가 부족할 때만 같은 실행에서 공식 링크를 보강한다. 현재 상한은 2회 탐색, 상세당 추가 URL 2개, 실행당 추가 URL 48개·모델 계획 8회다. 실제 한도는 공유 설정에서 확인한다. 선택 항목 누락만으로 재시도하지 않는다. [탐색 한도](../../worker/pipeline/fpds_collection_process.py)

수집 변경에는 같은 입력으로 재현할 수 있는 정상·경계·실패 사례를 둔다. 보존 원문과 기대값을 사용할 때 체크섬을 확인한다. 예상 체크섬을 바꾸어 실패를 지우지 않는다. 다운로드 성공, 후보 자동 검증, 실제 승인·상품 버전 기록은 각각 확인한다. 로컬 재생의 결과와 실제 은행 실행 결과를 따로 기록한다. [운영 가이드](../../descent/은행_상품_수집_검증_가이드.md)
