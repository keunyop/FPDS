## 비용을 줄이는 구현

- `scripts/maintenance/collection_accuracy_recovery.py`: 승인된 고정 manifest를
  검증하고, 상품 식별이 정확히 같은 보존 후보/근거를 현재 규칙으로 재평가한다.
  읽기 전용 트랜잭션이며 모델 요청이나 자동 재활성화는 하지 않는다.
- 명시적 통화가 캡처에 전혀 없으면 추출 AI 호출을 생략한다. 통화 언급의 존재만으로
  해당 상품의 통화를 확정하지는 않는다. 실제 출처·문구·의미 검증은 그대로다.
- AI 요청은 상품 식별·통화·현재 국가/상품 유형의 비교 필수 속성에 집중한다.
  Public 비교에 필요한 연이율/APY 구분과 중도 인출 가능 여부는 같은 근거에서
  확인되면 유지한다. 이를 위한 추가 검색은 하지 않는다.
- 동일한 출처/스냅샷/전체 청크/설정/모델/관련 코드/UTC 날짜의 성공한 추출 결과를
  재사용한다. 여기에는 근거 부족으로 빠진 항목도 포함한다. 원문이나 규칙이 바뀌면
  새로 처리하며, provider 오류는 재사용하지 않는다.
- 캐시는 출처별 비공개 파일 1개이고 기존 근거 보존 정책을 따른다. 다른 실행의
  원문을 현재 실행인 것처럼 표시하지 않는다. 새 추출 산출물은 run별 경로에 보존한다.
- 현재 실행이 실제 선택·파싱한 스냅샷만 추출에 사용할 수 있게 했다.
- 재사용 후에도 정규화·정확성 검증·자동 승격·Public 검증을 모두 거친다.
  이 캐시는 추출 단계에 적용된다. 별도의 dynamic normalization까지 재사용하는 것은 아니다.
- 사용량은 기존 bounded model_execution 메타데이터와 이번 비공개 실행 자료에서
  확인했다. 독립적인 비용/토큰 장부나 Admin 메뉴는 만들지 않았다.

실측 신규 Responses 요청 **6회**, 입력 **103,667**, 출력 **24,611** 토큰,
합계 **128,278** 토큰이다. 검색 도구의 개별 실행 횟수나 청구 금액을 의미하지 않는다.
정확한 달러 비용이나 전체 354개 재수집 대비 절감률은 계산하지 않았다.
Scotia 실제 캡처/추출 입력을 읽기 전용으로 재현했을 때 cache hit를 확인했고,
provider 함수가 호출되면 실패하도록 차단한 검사에서 **추가 요청 0회·토큰 0**이었다.
