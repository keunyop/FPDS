### 남은 운영 반영

검토 approve/reject/edit-approve/defer/ai-verify 5개 endpoint는 추가 코드에서
`410 product_review_retired`로 종료된다. 인증·역할·CSRF·국가 검사는 유지하고,
조회 응답도 `available_actions=[]`, `ai_verification.can_run=false`로 바꿨다.
현재 Vercel CLI는 logged out이므로 이 추가 변경을 배포하지 못했다.
**API 서비스만 다시 배포해야 과거 endpoint의 운영 종료가 완료된다.**
이미 적용한 DB 전환은 재실행할 필요가 없다. 새 유료 수집도 실행하지 않았다.

추가 검증: API 전체 535개, 전환 도구 회귀 4개 통과. 운영 `/healthz`,
CA/US products API 및 Public BFF 모두 HTTP 200/상품 0건. 페이지 캐시 갱신 후
`15:50:23Z`에 CA/US 홈과 상품 목록 4개 URL 모두 HTTP 200이며 HTML에 과거
상품 ID가 없음을 확인했다. 첫 조회의 남은 캐시와 최종 결과를 비공개 실행 기록에 보관했다.
독립 DB 조회로 이전 상품 버전 355개, 기존 결정 5건, 근거 연결 22,519개의 보존도 확인했다.

## 확인한 문제와 변경

| 확인한 문제 | 변경 |
|---|---|
| 일부 기본 상품 유형은 AI 근거 검사를 건너뜀 | 모든 유형에 동일한 최종 정확성 검사 |
| 숫자 포함 여부만으로 문장·불리언까지 통과 가능 | 타입·값·라벨·단위·명시적 긍정/부정 검사 |
| `1.5`의 구두점을 제거해 정수 `15`로 해석 가능 | 원래 JSON 타입 검사, 정수는 정수만 허용 |
| NaN/Infinity, 임의 term table 구조 허용 | 유한 수치와 행별 공통 스키마 강제 |
| 인용문 일부만 맞고 주변 조건이 누락될 수 있음 | 보관된 원문 문맥까지 검사, 복합/조건부 단일 금리 제외 |
| 국가에서 통화를 추정 | 검증된 원문의 ISO 코드·통화 이름 필요 |
| 정규화 모델이 이미 검증한 값을 재작성 가능 | 검증 후 새로운 사실 생성·값 변경 차단 |
| 검토 대기열과 후속 review-agent에 의존 | 자동 반영 또는 자동 제외, 새 수집의 사람 검토 없음 |
| 마지막 승인·집계 단계에서 검증이 약해질 수 있음 | 새 후보·canonical·Public에서 같은 내용 해시 재검사 |

불확실한 선택 항목은 제거한다. 상품명·통화·국가/유형별 비교 필수 항목이
충족되지 않으면 상품 후보를 제외한다. AI 신뢰도가 높다는 이유로 통과시키지
않는다. 원문은 비공개 근거로 남고 제외한 값은 새 상품 데이터에 반영되지 않는다.

Admin 주요 메뉴는 개요·실행·은행으로 정리했다. 과거 검토는 읽기 전용
이력으로 이동했고 승인·수정·보류·AI 검증 버튼과 일괄 선택을 제거했다.
실행 상세에서 자동 제외 수를 확인할 수 있다. Public은 새 검증을 통과한
상품만 기존 비교 화면으로 전달하며, 비공개 근거나 검증 메타데이터를 노출하지 않는다.

사유와 기존 미처리 review ID는 비공개 로컬 manifest에 기록했다.

- 과거 미처리 review: **470개** — queued 467개, deferred 3개.
- 원문 대조에서 상품 식별 근거 부족 189개, 명시적 통화 근거 부족 350개,

**355개가 전부 잘못된 사실이라는 판정은 아니다.** 현재 보관된 인용·출처·

미지원 표현도 보수적으로 제외된다. 인용문 자체만 검사한 중간 결과의
1개 통과는 주변 조건 검사 후 0개로 변경되었다.

## 승인 전 준비했던 전환안 — 위 적용 기록으로 완료 상태 확인

1. 적용 직전에 manifest의 상품 ID·현재 버전·payload 해시와 review ID·상태·
   갱신 시각을 대조한다. 하나라도 달라지면 변경하지 말고 감사 목록을 갱신한다.
2. 대상 355개 상품을 이력 보존 방식으로 비활성화한다. 기존 상품 버전과
   근거를 삭제하지 않고 사유가 기록된 새 버전/change event를 남긴다.
3. 대상 470개 미처리 review를 자동 제외로 종료한다. 과거 결정은 보존하고
   새 상품수집은 검토 대기열을 만들지 않는다.
4. 과거 상품 review의 수동 변경 API도 종료한다. 계정 가입 승인·권한·CSRF와
   운영상 외부 작업 승인 경계는 유지한다.
5. 트랜잭션 롤백 리허설 후 한정된 변경을 적용하고, CA/US Public 스냅샷을
   갱신해 inactive 상품이 노출되지 않는지와 반복 실행 무변경을 확인한다.
6. 필요한 은행/상품만 새 기준으로 범위를 정해 재수집한다. 무제한 유료 재수집은
   이번 작업에서 실행하지 않았다.

**영향: 현재 active 상품을 전부 비활성화하면 Public 상품 목록이 비게 된다.**
개발 DB가 Public 운영 환경과 공유되므로 실제 공개 화면에도 영향을 줄 수 있다.
이 전환안은 상품별 수동 리뷰 요청이 아니라 기존 데이터의 일괄 정책 전환이다.

자동 승인 검토가 과거 데이터 전체에 대한 즉시 gate 적용과 기존 변경 API의
일괄 종료를 거절했다. 이유는 새 수집 경계 없이 과거 업무와 공개 상품이 대량
중단될 수 있다는 점이었다. 따라서 첫 구현은 새 버전 검증 표시가 있는
데이터에 적용했고, 당시에는 과거 데이터와 API를 유지했다. 이후 Product Owner가 위 영향을 포함해 전환을 승인했으며, 실제 적용 결과와
추가 API 배포 경계는 문서 상단에 기록했다.
